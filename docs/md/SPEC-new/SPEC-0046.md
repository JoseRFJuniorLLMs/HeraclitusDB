# SPEC-0046 — Heraclitus Gov-Compliance: Sovereignty, Evidence & Regulatory Plane

**Status:** Draft / Proposed
**Autor:** Heraclitus Core & Security Team
**Data:** Agosto de 2026
**Classe:** Government Compliance / Sovereignty / Evidence / Privacy / Air-Gap
**Prioridade:** P0
**Alvos primários:**`heraclitus-compliance`, `heraclitus-sentinel`, `heraclitus-server`
**Integração:**`heraclitus-crypto`, `heraclitus-log`, `heraclitus-raft`, `heraclitus-tier`
**Compatibilidade:** Rust Stable
**Princípio:***Security evidence must remain verifiable even when networks, operators, AI models and external authorities are unavailable.*

---

# 0. Decisão Arquitetural

A SPEC-0046 estabelece o **Government Compliance Plane** do HeraclitusDB.

Seu objetivo não é simplesmente adicionar relatórios com nomes de normas brasileiras.

O objetivo é tornar requisitos de:

* soberania;
* cadeia de custódia;
* proteção de dados;
* retenção;
* classificação;
* temporalidade;
* assinatura;
* carimbo do tempo;
* operação desconectada;
* rastreabilidade decisória;

propriedades verificáveis da arquitetura.

O plano de compliance será construído sobre quatro pilares:

```text
SOVEREIGN EXECUTION
        +
CRYPTOGRAPHIC EVIDENCE
        +
REGULATORY POLICY ENGINE
        +
AUDITABLE REPORTING
```

# 1. Referenciais Normativos

O perfil `gov-br` MUST permitir mapear controles para, no mínimo:

* LGPD — Lei nº 13.709/2018;
* Resolução CD/ANPD nº 15/2024;
* IN GSI/PR nº 1/2020;
* IN GSI/PR nº 3/2021;
* NC nº 05/IN01/DSIC/GSIPR;
* NC nº 08/IN01/DSIC/GSIPR;
* NC nº 21/IN01/DSIC/GSIPR;
* Decreto nº 10.748/2021 — REGIC;
* Portaria GSI/PR nº 120/2022;
* PPSI vigente;
* documentos ICP-Brasil DOC-ICP aplicáveis;
* políticas arquivísticas e tabelas de temporalidade do órgão.

O próprio CTIR Gov lista NC-05, NC-08 e NC-21 em sua base normativa atual.

A NC-21 trata especificamente de registro de eventos, coleta e preservação de evidências.

A implementação MUST NOT codificar a premissa:

```text
regulation = eternal constant
```

Normas serão representadas como políticas versionadas.

# 3. Perfis Operacionais de Soberania

```rust
pub enum SovereigntyMode {
    Normal,
    ControlledEgress,
    StrictAirGap,
}
```

## 3.1 `Normal`

Pode utilizar recursos externos autorizados.

## 3.2 `ControlledEgress`

Somente destinos expressamente permitidos:

```text
ACT ICP-Brasil
repositório CRL/OCSP
feed de threat intelligence
gateway institucional
```

Todo egress MUST ser auditado.

## 3.3 `StrictAirGap`

Nenhuma conexão externa é permitida.

```text
network egress = DENY
```

Inclusive para:

* LLM remoto;
* telemetry SaaS;
* ACT;
* TAXII;
* atualização de modelos;
* atualização de regras.

# 4. Inferência Soberana

A SPEC-0046 NÃO obriga `heraclitus-gpu` a se transformar em runtime completo de transformers.

Isso seria outra especificação.

O contrato correto é:

```rust
#[async_trait]
pub trait SovereignModelBackend {
    async fn infer(
        &self,
        request: &ModelRequest,
    ) -> Result<ModelResponse, ModelError>;

    fn sovereignty(&self) -> ModelSovereignty;
}
```

```rust
pub enum ModelSovereignty {
    LocalProcess,
    LocalNetwork,
    External,
}
```

Em `StrictAirGap`:

```text
External       => DENY
LocalNetwork   => policy-dependent
LocalProcess   => ALLOW
```

# 7. `mlock` e Dados Sensíveis

Quando suportado pelo sistema operacional:

* contexto do incidente;
* credenciais transitórias;
* chaves;
* buffers contendo segredos;

SHOULD utilizar memória não paginável.

Falha em aplicar `mlock` MUST gerar telemetry, e em perfil de segurança estrito MAY abortar a inicialização do componente.

# 8. Base Atual de Carimbo do Tempo

O `heraclitus-compliance` já possui:

```text

HttpTsa
TsaClient

```

`LocalTsa` é explicitamente de desenvolvimento e não representa ACT ICP-Brasil. O código atual também reconhece que a verificação completa do token de produção ainda necessita validação da cadeia de confiança ICP-Brasil.

Portanto, a SPEC-0046 é uma evolução do subsistema existente.

# 12. Evidence Commitment

# 14. Air-Gap e Carimbo Externo

Um ambiente realmente isolado não consegue chamar uma ACT externa.

Consequentemente, MUST existir:

```text
Deferred External Anchoring
```

Fluxo:

```text
AIR-GAP

LSN range
   ↓
Merkle root
   ↓
EvidenceCommitment
   ↓
signed export package
   ↓
DATA DIODE / controlled media
   ↓

CONNECTED ZONE

RFC3161 / ICP-Brasil
   ↓
TimeStampToken
   ↓
controlled import
   ↓

AIR-GAP

verification
   ↓
EvidenceAnchor
```

# 16. Chain of Anchors

Cada anchor SHOULD referenciar o anterior:

```text
Anchor[n]
  prev_anchor_digest
```

criando:

```text
A0 → A1 → A2 → A3
```

Além do Merkle interno.

---

# 17. Escopo Probatório

A arquitetura MUST evitar expressões como:

```text
"prova jurídica inquestionável"
```

Hash, Merkle, assinatura e carimbo do tempo fortalecem verificabilidade de:

* integridade;
* origem;
* existência temporal;
* continuidade.

Eles NÃO substituem, isoladamente:

* procedimentos humanos;
* competência pericial;
* cadeia de posse;
* requisitos legais;
* avaliação judicial.

# 33. No Classification Downgrade

Um evento derivado não pode automaticamente possuir classificação inferior à de suas evidências.


# 37. Security Gates

## G0 — Air-Gap

Em `StrictAirGap`, tentativa de egress MUST falhar.

## G1 — Model Sovereignty

Backend externo MUST ser rejeitado.

## G2 — Trust Chain

Token ICP-Brasil não encadeado a trust anchor autorizado MUST falhar.

## G3 — Imprint

Token válido sobre imprint diferente MUST falhar.

## G4 — Tamper

Alterar qualquer evento ancorado MUST quebrar a prova Merkle.

## G5 — Legal Hold

Nenhum dado sob hold poderá ser destruído por operação automática.

## G6 — Privacy Export

Campo proibido pela política MUST ser removido antes do relatório externo.

# 40. Invariantes

```text
C1  Nenhuma política regulatória é hardcoded como eterna.

C2  Air-gap significa zero egress não autorizado.

C3  IA externa é proibida em StrictAirGap.

C4  LocalTsa nunca é apresentado como ICP-Brasil.

C5  Um anchor não é válido apenas porque o DER parseou.

C6  Prova temporal exige trust chain verificável.

C7  Merkle protege integridade, não substitui cadeia de custódia humana.

C8  Comunicação regulatória exige autorização institucional.

C9  RIPD != Comunicação de Incidente.

C10 Legal Hold prevalece sobre expurgo automático.

C11 Classificação é propagada a derivados.

C12 Toda avaliação registra versão da política.
```
